# Tallimo v0.2.0

Release notes for v0.2.0.

Tallimo now has the full page set on the Signal Consult design, in light and dark, at phone width. It is still alpha and runs in fixture mode.

## What's new

- Pick who you are on the first screen. Each role opens on its own page: developers and PMs on Today, the tech lead on Inbox, the principal PM on Leadership.
- Pages: Today, Inbox, Your desk, Your update, People, Projects, Activity, Leadership, Monday note, Connect, Settings.
- Attaching sources follows the role: developers and the tech lead attach GitHub repos, PMs and the principal PM attach Jira boards.
- Leadership commitment uses story assignments plus pull requests from the last 10 business days.
- The sample data uses fictional people.
- `TALLIMO_PORT` picks the port (default 8787), so you can click through on another port with a fresh database: `TALLIMO_PORT=8788 ROLLUP_DB_PATH=/tmp/tallimo-fresh.db cargo run -p rollup-api`. An invalid value stops the server at startup with a clear error.

## Fixes

Merges land in the right week in your time zone. Toasts show on the first screen. The principal PM no longer sees Sync. The build has zero warnings.

- A write (`/sync`, `/match`, `/map`, `/attach`, the review queue and project selection) whose Origin header names another site is refused with 403, so a page on another site can no longer start a sync or a match. Requests with no Origin, such as curl, still work (#33).
- Attaching on Connect (`/map` and `/projects/select`) refuses a missing or roleless person instead of writing for them (#29).
- A refused confirm in the review queue keeps the link the pull request already has; the confirm runs in one transaction (#30).
- A request whose Host is not this server (127.0.0.1, localhost or [::1], with or without its port) is refused with 421 before anything is read or written, so a page on a DNS-rebinding domain cannot reach the API (#32).

## Upgrade

On a fresh checkout: `cargo run -p rollup-api` from `crates/`, then load the sample once with `curl -X POST http://127.0.0.1:8787/sync`.

Coming from a v0.1.0 database: stop the server, move `crates/rollup.db*` aside to a dated backup outside the repo (for example `~/tallimo-backups/rollup-YYYY-MM-DD/`), then start v0.2.0 and post to `/sync` once.

```bash
# from the repo root, with the server stopped
mkdir -p ~/tallimo-backups/rollup-YYYY-MM-DD
mv crates/rollup.db* ~/tallimo-backups/rollup-YYYY-MM-DD/
```

Without this, Sync fails with a 500 (`UNIQUE constraint failed: identity_map.slack_member_id`), and the old people stay in the database. Never delete the old database: it may hold real data.

## Known issues

- Not yet clicked through by a person on the release build.
- Role checks are client-asserted (there is no session identity), so run it on 127.0.0.1 only.
- Fixture mode only.
- Whether the tech lead and the principal PM should attach anything is still an open product question.
